Ты — senior Python-разработчик, архитектор OCR/HTR-систем и специалист по созданию простых настольных приложений для цифровых гуманитарных наук. Твоя задача — спроектировать и написать законченное, рабочее, локальное GUI-приложение на Python для распознавания исторических славянских текстов (церковнославянский, старославянский, глаголица, старорусский, дореформенный русский) с сохранением в TXT, DOCX и PDF.

ГЛАВНОЕ ТРЕБОВАНИЕ: Это простое приложение для обычных пользователей (исследователей, историков, генеалогов). БЕЗ CLI, БЕЗ аргументов командной строки, БЕЗ терминала. Все действия — через понятный графический интерфейс.

РАЗДЕЛ 1: КОНТЕКСТ И НАУЧНАЯ БАЗА
═══════════════════════════════════════

При разработке ОБЯЗАТЕЛЬНО учитывай следующие доказанные факты из области HTR для славянских языков:

1. ДЕФИЦИТ ДАННЫХ: Для исторических славянских языков критически не хватает аннотированных датасетов. Приложение должно уметь работать с малыми данными и поддерживать дообучение.
2. МНОГОДВИЖКОВАЯ АРХИТЕКТУРА: Ни один движок не является универсальным. Реализуй три уровня:
   - Уровень 1 (Tesseract): Для печатных текстов и как fallback. ДОЛЖЕН поддерживать дообученные модели.
   - Уровень 2 (Kraken): Основной HTR-движок для рукописей. Полностью обучаемый анализ компоновки страниц. Локальное развертывание.
   - Уровень 3 (Transformer/TrOCR): Продвинутый уровень. Поддержка моделей TrOCR, LightOnOCR-2-1B-old-church-slavonic-line, trocr-handwritten-cyrillic.
3. СПЕЦИФИКА CSLAV: Церковнославянский требует поддержки титл, выносных букв, надстрочных знаков, лигатур и аббревиатур. Стандартные модели Tesseract НЕ работают. Необходима специализированная модель.
4. ГЛАГОЛИЦА: Поддержка глаголицы — самое слабое место экосистемы. Реализуй расширяемый адаптер для подключения внешних глаголических моделей. Не обещай встроенного качества.
5. ПРЕДОБРАБОТКА КРИТИЧНА: Исторические сканы имеют шум, затухание чернил, перекосы. Без предобработки точность падает на 20-40%. Конвейер предобработки — обязательный компонент.
6. ОЦЕНКА КАЧЕСТВА: Используй CER (Character Error Rate) как внутреннюю метрику. Отображай уверенность распознавания в GUI.
7. ИНТЕГРАЦИЯ CSLAV_OCR_1.0: Репозиторий Valentin-Kostin/CSLAV_OCR_1.0-main содержит ценную дообученную Tesseract-модель для церковнославянского. Приложение ДОЛЖНО:
   - Иметь механизм загрузки пользовательских traineddata файлов
   - Предоставлять слот для размещения специализированных CSLAV-моделей
   - НЕ копировать код из CSLAV_OCR_1.0 напрямую, но поддерживать формат его моделей
8. ОТКРЫТЫЕ ДАТАСЕТЫ: Приложение должно иметь справочный раздел со ссылками на ключевые ресурсы:
   - russian-old-orthography-ocr (для дореформенного русского)
   - Combined_Full_VKS_2 (для церковнославянского)
   - Codex Suprasliensis Project
   - Zenodo, CLARIN ERIC
9. ЛИЦЕНЗИОННАЯ ЧИСТОТА: Все зависимости должны иметь совместимые открытые лицензии. PySide6 предпочтительнее PyQt6 из-за LGPL.

Ограничения среды:
- Средний компьютер: CPU, 16–32 ГБ RAM, без обязательного GPU
- Полностью локальная работа, без облачных API
- Кроссплатформенность: Windows, Linux, macOS
- Python 3.10+

Стек технологий:
- GUI: PySide6 (предпочтительно) или PyQt6
- OCR: pytesseract, kraken (pip install kraken), transformers (опционально)

- PDF: PyMuPDF (fitz)

- Логирование: logging (стандартная библиотека)
- Опциональные движки: easyocr, paddleocr — только в requirements-optional.txt

РАЗДЕЛ 3: АРХИТЕКТУРА GUI
═══════════════════════════════════════

Интерфейс должен быть ПРОСТЫМ, ДРУЖЕЛЮБНЫМ, на русском языке.

Главное окно:
┌─────────────────────────────────────────────┐
│ Панель инструментов                          │
│ [Открыть файл] [Открыть папку] [Открыть PDF] │
│ [Распознать] [Отмена] [Экспорт] [Настройки]  │
├──────────────────┬──────────────────────────┤
│                  │                          │
│  Просмотр        │  Текстовый редактор      │
│  изображения     │  (редактируемый)         │
│  + зум/пан       │  + метки страниц         │
│  + навигация     │  + моноширинный шрифт    │
│                  │                          │
├──────────────────┴──────────────────────────┤
│ Статус-бар: прогресс | текущее действие      │
└─────────────────────────────────────────────┘

Требования к GUI:
1. QThread/QObject worker — ВСЯ тяжелая работа вне UI-потока
2. Сигналы: progress_changed, page_completed, error_occurred, finished
3. Кнопка «Отмена» останавливает worker корректно
4. При ошибке — дружелюбный QMessageBox, НЕ traceback
5. Placeholder-состояния: «Откройте файл», «Текст не распознан»
6. Всплывающие подсказки на всех элементах
7. Сохранение настроек в JSON автоматически
8. Редактируемый текст справа — экспорт использует ИСПРАВЛЕННЫЙ текст
9. Зум: колесо мыши + кнопки Fit/100%/Zoom In/Out
10. Навигация по страницам PDF/папки

Панель настроек (две вкладки):
Вкладка «Основные»:
- Выбор языка (выпадающий список + чекбоксы)
- Режим качества: Быстро / Сбалансировано / Высокое
- Движок: Авто / Tesseract / Kraken / Transformer
- Форматы экспорта: TXT ☑ DOCX ☑ PDF ☑

Вкладка «Дополнительно» (сворачиваемая):
- Параметры предобработки (чекбоксы + слайдеры)
- Путь к пользовательским моделям traineddata/ONNX
- Порог уверенности
- Включить/выключить метки страниц
- Режим отладки

Диалог экспорта:
- Выбор формата(ов)
- Выбор_scope: текущая страница / все страницы / выбранные файлы
- Кнопка «Открыть папку после экспорта»

═══════════════════════════════════════
РАЗДЕЛ 4: КОНВЕЙЕР ПРЕДОБРАБОТКИ
═══════════════════════════════════════

Режимы: fast / balanced / high

Операции (настраиваемые через GUI):
1. Grayscale conversion
2. DPI normalization (целевой DPI настраивается)
3. Deskew (автоповорот при перекосе)
4. Denoise (median/Gaussian blur, настраиваемая сила)
5. Contrast enhancement (CLAHE)
6. Adaptive binarization (порог настраивается)
7. Border crop (удаление черных рамок)
8. Artifact removal
9. Max dimension limit (защита от OOM на слабых ПК)

ВАЖНО: Для древних текстов агрессивная бинаризация может уничтожить тонкие штрихи. По умолчанию для CSLAV/старославянского — мягкий режим. Пользователь должен видеть preview предобработки ДО запуска OCR.

РАЗДЕЛ 5: МНОГОДВИЖКОВАЯ СИСТЕМА OCR
═══════════════════════════════════════

Архитектура engine adapter pattern:

engines/
├── base.py          # Абстрактный базовый класс OCREngine
├── tesseract_engine.py  # Уровень 1: печатные тексты, CSLAV traineddata
├── kraken_engine.py     # Уровень 2: основной HTR для рукописей
├── transformer_engine.py # Уровень 3: TrOCR, LightOnOCR, trocr-handwritten-cyrillic
└── factory.py           # Фабрика выбора движка по настройкам

Каждый движок возвращает стандартизированный PageResult:
- text: str
- confidence: float (0.0–1.0)
- engine_name: str
- language: str
- warnings: list[str]
- processing_time: float

Обработка отсутствующих моделей:
- Если Tesseract не установлен → показать окно с инструкцией установки
- Если языковой пакет отсутствует → предупредить, предложить скачать или выбрать другой язык
- Если Kraken/Transformer модель не найдена → graceful fallback на Tesseract + предупреждение
- НИКОГДА не падать с необработанным исключением

Поддержка пользовательских моделей:
- Настройка пути к папке с custom traineddata / ONNX / checkpoint
- Автоматическое обнаружение новых моделей в указанной папке
- Валидация формата модели перед использованием

═══════════════════════════════════════
РАЗДЕЛ 6: ЭКСПОРТ
═══════════════════════════════════════

TXT:
- UTF-8 с BOM (для совместимости с Windows)
- Опциональные метки страниц [Страница N]
- NFC-normalized Unicode

DOCX:
- python-docx
- Заголовок = имя исходного файла
- Разрывы страниц между страницами
- Моноширинный шрифт для распознанного текста
- Метаданные: дата распознавания, использованный движок

PDF:
- Текстовый PDF с распознанным текстом
- Optional: searchable PDF (изображение + невидимый текстовый слой)
- Fallback-шрифт если символы не поддерживаются
- Предупреждение при потере символов
